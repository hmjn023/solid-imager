# キャラクタークラスタリング: HNSW + HDBSCAN 実データ検証

2026-10-29にローカルPostgreSQLの保存済みCCIPを使って行ったPython初回実験の記録。現在の実行ツールは `apps/server/scripts/cluster-characters.ts` に置き換えた。操作方法は [TS版README](../../apps/server/scripts/character-clustering/README.md)、移行後の比較は [TypeScript検証記録](character-hdbscan-typescript-2026-10-29.md) を参照。Pythonの実行ファイルと依存定義は削除し、比較用の保存結果だけをローカルに残している。

## 結果

HNSWによる全対象の近傍グラフ構築と、疎な距離行列からのHDBSCANが実行できた。200枚単位で分類を分断する制約はない。一方、比較した設定では全画像を同一キャラクターごとにまとめ切れず、noiseと同名キャラクターの分断が多い。全自動のキャラクター割り当てとしては採用せず、人が確認する初回の候補生成に使う段階。

## 対象

| 項目 | 値 |
| --- | ---: |
| 保存済みCCIP | 91,726件 |
| 今回の対象 | 68,674枚 |
| 既存キャラクター付き | 23,735枚 |
| 既存キャラクターの種類 | 1,616 |
| 未分類 | 44,939枚 |

対象はactive画像、画像全体の現行CCIP、`solo` タグあり、既存キャラクター登録0〜1件、非ゼロベクトル。人物cropや人数モデルは使用せず、タグ誤りは残る。モデルは `ccip-caformer-24-randaug-pruned`、embedding version 1。距離はコサイン距離で、CCIP距離モデルの出力ではない。

既存のキャラクター情報は結果の監査にのみ使用した。名前を参照してクラスタを作ったり、既存の割り当てを更新したりしていない。

## 近傍グラフ

- PostgreSQLのpgvector 0.8.6。
- 既存HNSW `idx_ccip_embeddings_embedding_cosine` を使用。EXPLAIN ANALYZEで確認した。
- k=64、`hnsw.ef_search=256`、iterative scan=`strict_order`。
- batch size=128は受け取り単位。各画像の候補検索は全対象に対して実行した。
- READ ONLY / REPEATABLE READの同一snapshotを使用。
- 対称化後の辺数は3,180,118、連結成分は1個。
- 抽出と監査に513.392秒（約8分33秒）。全画像の近傍抽出部分は約494秒。
- 固定seedで選んだ16枚について、同じ対象全体からの正確な上位64件と比較した平均Recall@64は0.998046875（約99.8%）。サンプル監査であり、全点への保証ではない。

soloタグ条件を通常のEXISTSで結合すると、PostgreSQLが対象全体を毎回ソートする実行計画を選ぶケースがあった。タグチェックを相関サブクエリにし、HNSWが実際に使われなければ抽出を停止する実装にした。単にインデックスが定義されていることだけでは不十分。

## HDBSCANの比較

`metric=precomputed`、`algorithm=generic`、`allow_single_cluster=False`。N×Nの密行列は作らず、保存された近傍だけの疎行列を使用した。HNSWと疎化による近似があり、全距離行列を使うHDBSCANとの一致は保証しない。

### 指標の意味

- pair precision: 同じクラスタへ入った既存ラベル付き画像ペアのうち、名前が一致した割合。
- pair recall: 既存ラベルが同じ画像ペアのうち、同じクラスタへ戻せた割合。noiseへ落ちた画像も取りこぼしとして数える。
- 既存ラベルはAIやインポート由来の誤りを含み得るため、これらは識別精度の正解率ではない。未分類画像の正しさはこの集計だけでは検証できない。
- HDBSCANのmembership strengthは人物・キャラクターの識別確率ではない。

`leaf` では分類された画像同士のラベル一致は高いが、同名画像の分断が多い。k=32と64のleaf結果は、双方で分類された画像上のARIが0.9949、noise判定の一致率が98.29%だった。

今回の候補のうち、`eom / min_cluster_size=5 / min_samples=1` は35,230枚（全対象の51.3%）を1,899群へまとめた。既存ラベル付き画像のうち14,164枚、未分類画像のうち21,066枚がグループに入った。ただし33,444枚がnoiseに残り、既存ラベルの同名ペアの再現率も36.65%なので、全体を十分に整理できたとは言えない。

この設定はk=32でも64でも分割が完全に一致した。今回のデータではk=32を使うことで、保存済みグラフからの再実行を約7.4秒・約997MiBで行えた。ただし別データでもk=32で十分とは限らない。

`min_cluster_size` を3へ下げると5,058群へ細分化し、分類率や同名ペアの再現率が単純に改善するわけではなかった。k=32と64では、この条件の分割は完全に一致した。

## インクリメンタル化への判断

今回のボトルネックは、HDBSCAN本体（約7〜14秒）より全近傍の抽出（約8分半）だった。次に差分化するなら、まず近傍グラフを対象にするのが合理的。

1. 初回の全近傍グラフと、特徴量ID・モデル・抽出時刻を保存する。今回のツールで実施済み。
2. 新規・変更画像の近傍をDBインデックスで取得し、影響を受ける既存点の近傍も更新する。新点側の辺を追加するだけでは、既存点の近傍集合や密度が古いままになる。影響範囲を完全に捕捉できない方式なら近似であることを明示し、全体再構築と監査を併用する。
3. 更新済みグラフからHDBSCAN自体は全体を再実行する。run内クラスタ番号は変わり得るので、承認済みのキャラクターIDへ直接上書きしない。

日常の名前付けは別の処理とし、承認済みキャラクターの複数代表画像へ新規画像を照合する。候補間の差が小さいものは保留へ回す。保留群から新キャラクターを発見するときにHDBSCANを使う。

疎なprecomputed距離入力では標準の `approximate_predict` 用の予測データを作れない。また `approximate_predict` 自体も、新しいクラスタを発見するインクリメンタルHDBSCANではない。

グラフの差分更新や追加画像の自動割り当ては、この実験ツールには未実装。今回実装したのは、全対象のHNSW抽出、グラフと結果の保存、DBへ再接続しない再分類・比較。
