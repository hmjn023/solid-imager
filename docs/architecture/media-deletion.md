# メディア削除の確定と後処理

| 操作         | DB の削除                                                                                                 | コミット後の後処理と通知                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 単体削除     | ソースとメディアを照合し、ローカルパスを検証してからメディア行を削除                                      | ローカルファイルとサムネイルを削除し、`media-deleted` を1回発行する。削除や通知の失敗はログに記録する                                           |
| 一括削除     | 指定ソースに属する行を一括 DELETE し、返却行を対象にする。指定 ID が1件でも欠けたら全体をロールバックする | 確定した各行に単体と同じ後処理を適用する。ID の重複や競合で同じ削除の後処理を繰り返さない                                                       |
| 移動元の削除 | コピー先の行を作成し、同じトランザクションで元の行を削除                                                  | ファイルとサムネイルを削除し、移動元と移動先に `media-moved` を発行する。外部資源の削除失敗はコミット済みの移動を再実行できないエラーとして扱う |

メディア行が削除されると、`media_regions` とその `ccip_embeddings` が外部キーで同じトランザクション内に削除される。外部キーの削除に失敗した場合、メディア削除もロールバックされる。

外部トランザクションを受け取った操作は、削除対象を `DeferredActions` で返す。トランザクション所有者がコミット成功後に一度だけ実行する。コミットが失敗したり結果を確認できなかったりする場合、削除対象の元ファイルを保持し、確定通知も保留する。通知に失敗してもコミット済みの削除や移動は取り消さない。 移動コミット後のジョブ登録に失敗した場合も、元のファイルの削除と通知を試みる。
